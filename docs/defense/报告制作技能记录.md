# 项目开发报告制作技能记录

记录日期：2026-07-12  
用途：说明本项目开发报告如何检索技能、建立计划、取证、审阅和交付。

## 1. 实际使用的技能

| 技能 | 来源 | 采用方式 |
|---|---|---|
| `using-superpowers` | 本地系统技能 | 先建立计划，再执行取证、写作、审阅和交付，不直接凭感觉写报告 |
| `documentation` | 本地技术文档技能 | 使用架构文档的组件、数据流、技术选型、监控和安全结构 |
| `technical-writer` | OneWave-AI/claude-skills，约 213 GitHub stars，skills.sh 约 857 installs | 使用受众分析、短句、可扫描标题、代码/图表、质量清单和维护说明 |

| `documents` | 本地文档技能 | 用固定 DOCX 版式、表格几何、图片替代文字、结构审计和渲染门禁生成 Word |
| `find-skills` / `skill-installer` | 本地技能发现/安装技能 | 从 skills.sh 和 GitHub 检索候选并实际安装适用技能 |

## 2. 检索与选择原则

检索到的 `latex-thesis-zh`、Notion 研究汇总和成熟向量检索类技能没有直接套用。原因是本项目需要的是“基于真实代码的工程开发报告”，不是从零写学位论文，也不是企业知识库搜索。技能选择优先考虑来源透明、安装量、是否能指导代码取证、是否支持 Mermaid 和可复现命令。

## 3. 计划与验收流程

1. 读取项目规格、README、架构、API、schema、seed、源码和已有验收日志。
2. 并行核对后端、前端、Agent、部署和旧报告，建立事实基线。
3. 重新运行 `mvn.cmd test`、`npm.cmd run build`、Agent smoke、并发库存脚本和 `docker compose ps`。
4. 按“需求 -> 实现 -> 证据 -> 限制”重组终稿，AI 章节单独展开工具、记忆、安全和降级。
5. 以答辩老师视角审阅，主动修正测试数字、事务描述、知识库行数、旧路径和课程证据缺口。
6. 生成 Markdown、Word 和答辩预审记录，执行标题、表格几何、无障碍和链接检查。

## 4. 事实校准原则

- 运行时使用 `LIKE`，报告不把 schema 中的 ngram 索引写成已启用的全文查询。
- 订单创建使用 `TransactionTemplate(REQUIRES_NEW)`，报告不把源码写成不存在的 `@Transactional create`。
- 偏好提炼是规则优先、LLM 补充，报告不声称每轮必调大模型。
- `knowledge_chunk` 当前行数为 0，报告不沿用旧材料中的固定块数。
- 后端当前实测为 30 项通过，旧的 20/27 数字只在预审清单中作为待同步提醒。
- Codex 记录不能替代课程要求的 Claude Code 原始截图；报告明确列为待补材料。

## 5. 交付文件

- `docs/defense/项目开发报告-终稿.docx`：Word 版，已完成结构、表格几何和无障碍审计。

当前环境未安装 LibreOffice，DOCX 无法通过该工具渲染成 PNG；因此报告没有宣称完成视觉渲染验收，而是保留结构审计结果并在最终交付说明中注明限制。
