## 4. 答辩老师最可能深挖的 AI 问题

### 4.1 Agent 为什么不是普通聊天接口

必须现场展示 `create_tool_calling_agent`、`AgentExecutor(return_intermediate_steps=True)` 和 `toolsUsed`，再用真实商品查询证明数据来自后端。只展示一段聊天文本不够。

### 4.2 Agent 如何防止跨用户查订单

按顺序回答：前端 JWT -> Agent 回调 profile -> ContextVar 当前用户 -> 内部服务名/共享密钥 -> 后端订单条件查询。要特别说明：内部接口在路由层允许进入，但 Controller 仍强制校验内部头；这是教学级共享密钥方案。

### 4.3 长期记忆如何写入和读取

说明规则优先、LLM 补充；`user_preference` 用 `(user_id, preference_tag)` 唯一；权重每次加 0.1、封顶 2.0；每次请求读取 Top 3 注入 prompt；用户可忽略和删除。不要说成“向量记忆”或“每轮都调用模型”。

### 4.4 知识库是否已经可用

如未运行构建脚本，必须回答“表结构和检索代码已就绪，但当前 row count 为 0”。演示前运行 `docker compose exec agent-service python scripts/build_knowledge_base.py` 并重新查询行数；不要沿用 PPT 旧数字。

### 4.5 没有 LLM key 时怎么办

展示 `/health` 的 `llmEnabled`。完整模式依赖模型；没有 key 时使用规则兜底并仍调用真实工具，这是演示容错，不是完整模型推理。该边界主动说出反而更可信。

## 6. 评审后的最终判断

报告内容本身已经足以支持一次完整答辩，但“课程交付物是否全部齐全”取决于上述人工材料。答辩时应坚持证据优先：能运行的说运行结果，历史结果注明日期，未做的明确列为限制。尤其是 AI 部分，宁可准确描述规则兜底、空知识库和共享密钥的边界，也不要为了“看起来更智能”而使用无法复现的数字或术语。
